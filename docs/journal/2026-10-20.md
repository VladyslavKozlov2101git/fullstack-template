  argument against keeping it. Component folders are copied from a neighbour now; [[Tech-stack]],
  [[Local-setup]] and [[Frontend]] updated.

- 17:05 · decision · Five of the plan's decisions did not survive contact with AdminJS and were
  revised in `../specs/002-admin-panel/`: the official Nest adapter is unusable under pnpm, a
  nested `rootPath` serves a broken frontend, tiptap needs pinning or the API will not boot, the
  panel's own assets 404 under pnpm's `.pnpm` directory, and `main.ts` has to own body parsing or
  the login hangs. Each is written up under Deliberate oddities on [[Admin-Panel]].
- 17:05 · lint · The staged-credential scan stopped the work twice over a test fixture that read
  like a hardcoded password. Both false positives; the code was rewritten rather than the hook
  bypassed — [[0003-hooks-enforce-not-prose]] working as intended.
- 18:20 · decision · Review of [[Admin-Panel]] found four real defects, none of which the build
  had caught, because every check during it ran with `NODE_ENV=development`: the API did not boot
  at all in production (AdminJS bundles components unless `ADMIN_JS_SKIP_BUNDLE` is set, and the
  rejection is fatal); the panel could never hold a session behind nginx without `trust proxy`;
  the password digest was recoverable through list filters by blind prefix search; and the
  body-parser exclusion was case-sensitive while Express routing is not, which hung the
  connection on `POST /ADMIN/login` without logging in. All four fixed with tests; the measured
  evidence is in `../specs/002-admin-panel/spec.md`.
- 18:20 · dev · [[Known-Gaps]] gained the in-memory session store. [[Deploy]] gained the
  `trust proxy` requirement. The claim that the panel was verified through a real nginx was
  narrowed to what that check actually exercised — routing and CSP over plain http, not the
  Secure-cookie path.
